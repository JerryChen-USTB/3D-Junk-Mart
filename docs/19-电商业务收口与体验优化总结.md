# 19-电商业务收口与体验优化总结

## 1. 本轮目标

本轮工作以 `3dv-junk-mart` 主仓库为中心，目标是把项目从“3DGS 发布链路可跑通的演示型应用”推进到“具备完整电商业务闭环、可直接向用户展示”的产品状态，同时补齐近期联调中暴露出的交互和展示问题。

本次收口覆盖三条主线：

1. 电商业务闭环补齐
2. 3DGS 发布与商品管理能力补齐
3. 面向真实用户演示的前端体验修复与优化

## 2. 已完成的业务能力

### 2.1 用户与会话

- 登录、注册、游客模式
- 合成 `guest session`，空库也能正常启动和进入首页
- 个人资料编辑、头像上传与资料同步
- 退出登录确认

### 2.2 商品与交易

- 商品首页、搜索、详情页
- 收藏、聊天、下单、订单详情
- 卖家发货、买家确认收货、取消订单、纠纷入口
- 评价草稿、评价提交、商品评价列表
- 钱包、会员、通知、地址管理

### 2.3 3DGS 商品发布

- 视频创建 reconstruction task
- 启动远程训练
- Mask 抠图交互与预览确认
- Viewer 四步校准
- 发布为 marketplace listing
- 商品卡片默认展示封面，点击后才激活 3D Viewer

## 3. 后端收口内容

### 3.1 API 与状态安全

- 修复空数据库启动依赖默认用户的问题
- `GET /auth/session` 在无登录态或无效 token 下回退为 guest session
- reconstruction 写接口强制鉴权并校验任务归属
- task 与 listing 的卖家归属关系补齐
- 发布后自动回写 listing 的 3D 资源与封面信息

### 3.2 电商接口补齐

- 会话创建、消息查询、发消息、已读同步
- 订单创建、发货、确认收货、取消、纠纷
- 评价草稿、评价提交、评价标签、商品评价列表
- 钱包、会员、通知、地址 CRUD 与页面 bootstrap

### 3.3 部署与运维

- 增加 `deploy/linux/systemd/` 服务定义
- 增加 `deploy/linux/nginx/` 反向代理示例
- 增加 `deploy/linux/logrotate/` 日志轮转配置
- 增加运行时备份与健康检查脚本
- 补齐部署说明文档和环境变量样例

## 4. Flutter 前端收口内容

### 4.1 真实业务页面

- 消息列表与会话详情
- 结算页与订单详情页
- 钱包、会员、通知、地址、评价页面
- 首页与搜索页改为真实后端驱动

### 4.2 商品管理

- 我的商品支持编辑与删除
- 商品封面支持上传与替换
- 商品卡片默认显示封面，按需加载 3D Viewer
- 同一时刻只激活一个卡片 Viewer，降低内存压力

### 4.3 资料与首页同步

- 更新头像后，`Profile` 与 `Profile settings` 统一读取最新资料
- 编辑商品或更换封面后，首页、搜索、我的商品列表可及时刷新
- 补齐 guest 模式下的只读拦截逻辑

## 5. 近期重点优化与修复

### 5.1 商品卡片与详情页

- 商品属主不再看到“立即购买 / 联系 / 评价”
- 商品详情页补齐卖家头像和更稳定的地区展示
- 统一修复 `Unknown location` 回退逻辑

### 5.2 搜索与聊天

- 修复搜索按钮点击后结果不立即刷新的问题
- 重做会话详情页头部和消息区布局
- 修复聊天页顶部悬浮卡片错位、输入不可用的问题

### 5.3 封面上传与裁切

- 发布 3D 商品和编辑商品时都支持上传封面
- 封面调整页改为与商品卡片显示效果一致的横向裁切框
- 支持拖动与缩放对齐封面显示区域
- 修复图片方向归一化问题，避免手机照片方向错乱
- 裁切结果与卡片显示效果保持一致

### 5.4 Mask 抠图标注

- 修复标注页图片被压缩的问题
- 改为按真实图片显示区域计算点击坐标与标注点位置
- 本地预加载图和网络图统一为等比显示

## 6. 测试与验证

本轮已完成的基础验证：

- `flutter test`
- `python -m unittest discover`

验证重点包括：

- 空库启动与 guest session
- 会话创建、消息流转、订单链路、评价链路
- Flutter 侧登录、个人页、商品页、搜索、封面调整等主流程

## 7. 当前已知边界

### 7.1 远程训练服务依赖网络环境

远程 3DGS 训练服务当前部署在：

`http://222.199.216.192:9000`

如果不在校园网环境下，仍然可能出现以下限制：

- 无法启动新的远程训练任务
- 无法完整验证“上传视频 -> 训练 -> 发布 3D 商品”全链路

但以下内容仍可本地验证：

- 登录、游客模式
- 首页、搜索、商品详情
- 聊天、下单、订单、评价
- 已发布商品的 3D Viewer 浏览

### 7.2 当前架构取舍

本期仍然沿用现有 SQLite + records 存储模型，没有在本轮切换到更重的仓储层重构方案。这样做的原因是优先保障交付和联调效率，后续如需继续扩展平台级能力，再做数据层结构化升级会更稳妥。

## 8. 结论

截至本轮收口，`3dv-junk-mart` 已不再是单一 3DGS 演示仓库，而是具备以下特征的完整产品原型：

- 有完整电商业务闭环
- 有 3DGS 商品发布与展示链路
- 有部署、健康检查与备份工件
- 有针对移动端真实使用场景的交互与内存优化

后续若继续推进，建议优先做两件事：

1. 在校园网环境下完成远程 trainer 真机 smoke 测试
2. 在此基础上再补充更系统的集成测试与展示数据准备
