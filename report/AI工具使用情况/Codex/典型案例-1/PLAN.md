# 第一期实施计划：把“逛、看、问、下单”做扎实

## 摘要
按“闲鱼的交易关系 + 淘宝的交易中心”实施第一期，目标是把买家主链路做成高完成度闭环：

`首页逛商品 -> 搜索筛选 -> 商品详情决策 -> 聊天/议价 -> 结算下单 -> 模拟支付 -> 卖家发货 -> 买家收货/基础售后`

本期重点不是扩外围功能，而是把 5 个核心面做扎实：商品信息密度、搜索分发、聊天议价、订单状态机、交易中心 UI。  
同时修复当前聊天详情页“只剩安全提醒、没有任何可操作区”的前端布局 bug。

## 关键改动

### 1. 后端契约与状态模型
- 扩展 `backend/app/routes/marketplace.py` 与 `backend/app/schemas.py`，把订单、聊天、搜索、通知的数据结构从 MVP 提升到交易中心级别。
- 订单改成两段式：
  - 创建订单后先进入 `pending_payment`
  - mock 支付确认后进入 `awaiting_shipment`
  - 主链路为 `pending_payment -> awaiting_shipment -> shipped -> completed`
  - 侧支链路为 `cancelled / refund_requested / refunded / disputed`
- 订单数据明确拆成三层状态：
  - `payment_status`: `pending|paid|refunding|refunded`
  - `shipping_status`: `pending|awaiting_shipment|shipped|delivered|cancelled`
  - `aftersale_status`: `none|refund_requested|refunded|disputed`
- 新增订单动作接口：
  - `POST /orders/{id}/mock-pay`
  - `POST /orders/{id}/refund-request`
  - `POST /orders/{id}/approve-refund`
  - `POST /orders/{id}/reject-refund`
  - 保留并重做 `ship / confirm-receipt / cancel / dispute`
- 订单详情返回结构补齐：
  - `order_no`
  - 商品快照、成交价、原价、优惠、运费、实付款
  - 收货地址快照
  - 支付卡片
  - 物流卡片与物流节点
  - 售后卡片
  - 时间轴
  - 当前用户可执行动作列表
- 聊天增加议价能力：
  - 引入 `conversation_offer` 记录
  - 消息类型扩成 `text|offer|system`
  - 新增出价、还价、接受、拒绝的接口与响应字段
  - 一个会话同一时刻只允许一个活跃议价单
  - 接受后的议价单可作为下单价格来源
- 搜索与商品列表增加交易决策字段：
  - `condition_level`
  - `shipping_fee / shipping_promise`
  - `is_negotiable`
  - `is_favorited`
  - `seller_trust` 摘要
- 搜索接口支持：
  - `sort`
  - `price_bucket`
  - `location`
  - `condition_level`
  - `only_3d`
  - `only_negotiable`
- 通知结构补齐：
  - `category`
  - `icon_key`
  - `cta_action`
  - `cta_target`
  - `read_state`
  - 让通知页能直接跳转到订单、聊天、商品详情
- 地址结构补齐：
  - `label`
  - `is_default`
  - `full_address`
  - 支持新增、编辑、删除、设为默认的完整前端流

### 2. Flutter 主链路重构
- 首页与搜索页从“静态列表页”升级成“可逛的市场页”：
  - 首页接 `pages/home` 与 `home/feed`
  - 使用 banner、分类、推荐、3D 专区、快捷入口
  - 搜索页接 `search/suggestions` 与 `search/facets`
  - 增加热搜、历史、筛选抽屉、排序、空态与无结果建议
  - 增加商品收藏与“我的收藏”入口
- 商品详情页从“展示页”升级成“决策页”：
  - 顶部改成商品核心信息区，不让 3D 预览独占决策信息
  - 增加成色、瑕疵、发货地、发货承诺、是否议价、卖家信用、服务提示
  - 3D 预览保留，但作为详情里的高价值媒体模块
  - 补收藏、联系、立即购买、议价入口
- 聊天页重做为交易聊天页：
  - 固定顶部会话头部
  - 固定商品交易卡
  - 消息区展示文本消息、议价消息、系统消息
  - 底部固定输入区 + 快捷话术 + 出价入口
  - 接受议价后可直接发起按成交价下单
- 结算页重做：
  - 地址卡、商品卡、价格明细卡、备注区、支付方式卡
  - 提交订单后进入 mock 支付确认页，而不是直接已支付
- 订单中心重做：
  - 订单列表增加角色视角与状态分组
  - 订单详情改为淘宝式信息堆叠卡片：
    - 状态头图/横幅
    - 商品卡
    - 物流卡
    - 地址卡
    - 金额卡
    - 支付卡
    - 时间轴卡
    - 售后卡
    - 底部固定动作栏
  - 买家、卖家视角使用不同按钮组
- 通知页和地址页重做：
  - 通知按订单/消息/系统分组，卡片展示时间、摘要、主动作
  - 地址页改成高信息密度卡片，支持默认地址徽标、编辑、删除、设默认
- 共享 UI 组件抽出一层电商组件：
  - 状态横幅
  - 金额摘要行
  - 物流节点
  - 地址卡
  - 交易动作栏
  - 通知卡
  - 议价气泡
  - 让订单、通知、地址、结算、聊天复用一套视觉语言

### 3. 聊天 bug 修复与回归约束
- 重写 `app/lib/features/chat/chat_pages.dart` 的详情页布局：
  - 顶部信息区与商品卡固定
  - 消息区单独滚动
  - 输入框放到稳定的底部区域，不再依赖当前脆弱的 `Column + Expanded + SafeArea` 组合
- 输入区必须键盘安全：
  - 使用 `viewInsets.bottom` 驱动底部抬升
  - 小屏 Android 上输入框和发送按钮始终可见、可点
- 空会话时必须稳定显示：
  - 空消息卡片
  - 快捷问候
  - 输入框
  - 不允许出现“只剩安全提醒、其余全部空白”的状态
- 聊天消息至少支持三种卡片：
  - 普通文本
  - 议价卡片
  - 系统状态卡片
- 会话页增加直接下单/查看订单入口，避免聊天和交易断开

### 4. 实施顺序
- 先做后端状态模型和接口扩展，再做 Flutter repository/type 适配。
- 第二步做共享电商组件与视觉基线，再批量替换订单、通知、地址、结算、聊天页面。
- 第三步打通议价到下单的链路，再补首页/搜索/收藏的“逛”和“看”。
- 最后做测试矩阵、空态/异常态、角色差异和 UI 收口。

- 后端单测：

  - 卖家发货、买家确认收货

  - 接受议价后的订单金额使用成交价
  - 搜索筛选、收藏、通知跳转目标、地址默认切换
- Flutter/widget 测试：
  - 聊天详情页在小屏和键盘弹起时输入区仍可见
  - 空会话状态可见并可发送首条消息
  - 订单列表和订单详情在各状态下显示正确卡片和按钮
  - 通知卡点击跳转正确页面
  - 地址页新增/编辑/删除/设默认的状态刷新正确
- 端到端 smoke：
  - 浏览首页 -> 搜索筛选 -> 商品详情 -> 发起聊天 -> 议价 -> 接受 -> 结算 -> mock 支付 -> 卖家发货 -> 买家确认收货

  - 售后申请/退款/纠纷分支
  - 收藏商品 -> 从收藏重新进入详情
- 手工 UI 验收：
  - 订单、通知、地址、聊天四页在视觉上达到“淘宝式高信息密度卡片”标准
  - 页面在 Android 真机窄屏下不出现空白、遮挡、输入区不可点问题

## 假设与默认决策
- 产品基线采用“混合方案”：
  - 逛、看、问偏闲鱼
  - 订单、通知、地址、履约偏淘宝
- 第一期开启基础议价，且一个会话只维护一个活跃议价单。
- 不接真实支付，使用 mock 支付确认页模拟支付完成。
- 第一阶段售后做到“退款申请/卖家处理/纠纷升级”的基础版，不做真实退货逆向物流和图片举证。
- 仍按单商品、单数量、单卖家订单模型实施，不引入购物车和多商品合单。
- 卖家侧继续使用现有 App 内“我的商品/订单”承载，不单独建设商家后台。
- 钱包、会员不作为本期重点，只做与新订单状态兼容的最小适配。
