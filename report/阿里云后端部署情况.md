## 8. 当前遗留问题

从阿里云服务器访问原远程 3DGS 训练服务：

```text
http://222.199.216.192:9000/health
```

结果为连接超时：

```text
curl: (28) Connection timed out
```

这说明阿里云服务器当前无法访问该训练服务。影响范围如下：

- 普通电商业务接口不受影响。
- 已同步到服务器本地 `storage` 的图片、封面、静态资源可以正常访问。
- 新上传视频并启动 3DGS 训练的链路可能不可用。
- 如果某些 3D 模型资源仍依赖远程 trainer 的 `/storage/...` 路径代理，也可能受到影响。

后续可选解决方式：

1. 确认远程 GPU 训练服务器允许阿里云公网 IP 访问。
2. 将 3DGS trainer 服务也部署到阿里云服务器或同一内网。
3. 将已有 3D 模型资产完整同步到阿里云本地 `storage/models/`，减少对远程 trainer 存储代理的依赖。

## 9. 模型缓存恢复与 Viewer 修复

后续排查发现，原本能够在手机本地查看的 3D 模型并不在 `3dv-junk-mart/storage/models/` 目录中，而是曾经由手机 WebView 通过 `http://127.0.0.1:8000` 这一 origin 缓存在 IndexedDB 中。通过 ADB 安装同包名 debug APK 后，使用 `run-as com.example.app` 读取 App 私有目录，找到了以下缓存位置：

```text
/data/user/0/com.example.app/app_webview/Default/IndexedDB/http_127.0.0.1_8000.indexeddb.blob/1/00/
```

成功恢复出 5 个真实 PLY 模型文件：

| task_id | 恢复文件 | 文件大小 |
| --- | --- | --- |
| `task_20260416_104856_03e7f5` | `model.ply` | 50,790,257 bytes |
| `task_20260416_182909_35b115` | `model.ply` | 37,343,697 bytes |
| `task_20260416_205239_4c8f88` | `model.ply` | 46,865,657 bytes |
| `task_20260417_085706_d64cbe` | `model.ply` | 14,937,888 bytes |
| `task_20260417_090803_d3fc1c` | `model.ply` | 12,627,024 bytes |

这些模型已经同步到本地项目：

```text
D:\Projects\3dv-junk-mart\storage\models\<task_id>\model.ply
```

同时也已同步到阿里云服务器：

```text
/data/3dgs-marketplace/backend/models/<task_id>/model.ply
```

并且已将数据库中 3D 商品的 `viewer_url` 从原来的远程代理路径：

```text
/proxy/storage/models/<task_id>/model.ply
```

修正为后端本地静态资源路径：

```text
/storage/models/<task_id>/model.ply
```

修复后验证通过：

```text
http://101.201.74.180/storage/models/task_20260416_205239_4c8f88/model.ply
http://101.201.74.180/storage/models/task_20260417_090803_d3fc1c/model.ply
```

均返回 `200 OK`，商品接口中的 `viewer_url` 也已全部指向 `/storage/models/.../model.ply`。因此当前 APK 查看已有 3D 商品时，不再依赖原 `222.199.216.192:9000` 训练服务。
