# 训练服务服务器部署准备说明

更新时间：2026-04-09

本文档的目标不是“替你直接部署服务器”，而是把当前仓库整理到**可以按步骤部署 trainer_service 服务器**的状态。

当前推荐架构：

```text
手机 / Flutter
   -> 本地业务后端 backend
   -> 远程训练服务 trainer_service

backend:
- 本地任务镜像
- 本地 viewer 静态资源
- 本地业务流程

trainer_service:
- 远程任务真相源
- 远程训练执行
- 远程模型文件 / 日志 / mask 产物
```

## 1. 当前已经具备的部署前提

代码层面已经完成：

1. `trainer_service` 提供公开任务 API：创建、查询、列表、开始、取消、Mask 预览、Mask 确认、删除、viewer 配置更新
2. `trainer_service` 提供内部控制 API：`/internal/tasks/*`
3. `backend` 已通过 `gs_client` 调远程训练服务
4. `backend` 返回给 Flutter 的 `viewer_url` 继续走本地 `viewer/`
5. `backend` 返回给 Flutter 的 `model_url` 指向远程训练服务 `/storage/*`
6. 本地 backend 现在只需要知道远程 `GS_SERVICE_BASE_URL`

## 2. 服务器需要准备什么

服务器上需要：

1. 仓库代码
2. `conda:3dgs_app`
3. `conda:sam2_app`
4. `ffmpeg` / `ffprobe`
5. `colmap`
6. `node` / `npx`
7. CUDA / GPU 驱动

建议目录示例：

```text
/opt/3dgs-app/repo
/data/3dgs-storage
```

## 3. 服务器环境变量

最少需要：

```bash
export STORAGE_ROOT=/data/3dgs-storage
export VIEWER_ROOT=/opt/3dgs-app/repo/viewer
export TRAINER_SERVICE_PUBLIC_BASE_URL=https://trainer.example.com
export TRAINER_SERVICE_AUTH_TOKEN=replace-with-an-internal-secret
export SAM2_PYTHON=/opt/conda/envs/sam2_app/bin/python
export PRUNING_PYTHON=/opt/conda/envs/3dgs_app/bin/python
export COLMAP_COMPAT_REAL_EXE=/usr/local/bin/colmap
```

说明：

1. 当前服务器不需要托管 viewer 静态资源，但代码里仍保留 `VIEWER_ROOT` 兼容变量
2. 如果 backend 访问 trainer_service 用的是内网地址、`127.0.0.1` 或反代前地址，应该额外配置 `TRAINER_SERVICE_PUBLIC_BASE_URL`，让返回给手机的 `model_url` 指向可公开访问地址
3. `TRAINER_SERVICE_AUTH_TOKEN` 是可选的，仅用于保护内部 `/internal/tasks/*`

## 4. 启动命令

在服务器上：

```bash
cd /opt/3dgs-app/repo
source /opt/conda/bin/activate 3dgs_app
python -m pip install -r trainer_service/requirements.txt
python -m uvicorn trainer_service.app:app --host 0.0.0.0 --port 9000
```

## 5. 业务后端本地需要配置什么

业务后端本地只需要：

```powershell
$env:GS_SERVICE_BASE_URL = "http://<trainer-server>:9000"
$env:STORAGE_ROOT = "D:\Projects\3dgs-app\storage"
$env:VIEWER_ROOT = "D:\Projects\3dgs-app\viewer"
```

重点：

1. backend 本地 `STORAGE_ROOT` 不再要求和服务器一致
2. 本地 `STORAGE_ROOT` 现在主要保存任务镜像和业务态
3. 本地 `viewer/` 继续用于 WebView 与调试工具页

## 6. 反向代理建议

如果服务器前面接 Nginx，最简单是全量反代给 `uvicorn`：

```nginx
server {
    listen 80;
    server_name trainer.example.com;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 7. systemd 示例

可参考：

```ini
[Unit]
Description=3DGS Trainer Service
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/3dgs-app/repo
Environment=STORAGE_ROOT=/data/3dgs-storage
Environment=VIEWER_ROOT=/opt/3dgs-app/repo/viewer
Environment=TRAINER_SERVICE_PUBLIC_BASE_URL=https://trainer.example.com
Environment=TRAINER_SERVICE_AUTH_TOKEN=replace-with-an-internal-secret
Environment=SAM2_PYTHON=/opt/conda/envs/sam2_app/bin/python
Environment=PRUNING_PYTHON=/opt/conda/envs/3dgs_app/bin/python
Environment=COLMAP_COMPAT_REAL_EXE=/usr/local/bin/colmap
ExecStart=/opt/conda/envs/3dgs_app/bin/python -m uvicorn trainer_service.app:app --host 0.0.0.0 --port 9000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## 8. 部署前必须验收的接口

至少验收：

1. `GET /health`
2. `POST /tasks`
3. `GET /tasks/{task_id}`
4. `POST /tasks/{task_id}/start`
5. `POST /tasks/{task_id}/cancel`
6. `POST /tasks/{task_id}/mask-preview`
7. `POST /tasks/{task_id}/mask-confirm`
8. `PUT /tasks/{task_id}/viewer`
9. `DELETE /tasks/{task_id}`
10. `GET /storage/models/<task_id>/...`

## 9. 当前还没做的真正部署动作

下面这些仍需要你在真实服务器上执行，但代码已经准备到位：

1. 申请服务器域名或固定地址
2. 开放 9000 或经反向代理开放 80/443
3. 配置 systemd / Supervisor / NSSM 等守护
4. 配置 HTTPS
5. 配置日志轮转与磁盘清理
6. 准备 SAM2 模型缓存

## 10. 一句话结论

当前仓库已经到达这样一个状态：

**训练服务可以独立部署到服务器；业务后端继续本地开发运行；viewer 继续留在业务后端，本地通过远程 `model_url` 加载服务器模型。**
