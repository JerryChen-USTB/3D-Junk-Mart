# 前后端启动方法

更新时间：2026-04-09

本文以当前代码为准，描述现在推荐的启动方式：

```text
Flutter App
   -> backend（本地业务后端）
   -> trainer_service（远程训练服务，部署在服务器）
   -> 服务器 storage（任务、日志、模型）

viewer 静态资源继续由 backend 本地挂载
viewer 页面中的 model URL 指向远程 trainer_service /storage/*
```

如果你只做业务后端或 Flutter，本地默认不需要安装 COLMAP / CUDA / nerfstudio / SAM2。

## 1. 推荐启动模式

### 1.1 本地业务开发模式

你本地启动：

1. `backend`
2. `mobile_app`

服务器上启动：

1. `trainer_service`

### 1.2 本地全链路验证模式

只有在你要改训练链路、Masking、导出时，才建议本机同时启动：

1. `backend`
2. `trainer_service`
3. `mobile_app`

## 2. 关键环境变量

### 2.1 业务后端

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `STORAGE_ROOT` | 本地任务镜像目录根 | `<repo>/storage` |
| `VIEWER_ROOT` | 本地 viewer 静态资源目录 | `<repo>/viewer` |
| `GS_SERVICE_BASE_URL` | 远程训练服务地址 | `http://127.0.0.1:9000` |
| `GS_SERVICE_TIMEOUT_SECONDS` | 后端请求训练服务超时 | `30` |
| `BACKEND_PIPELINE_MOCK` | 是否走 mock 训练模式 | `false` |

兼容说明：

1. `TRAINER_SERVICE_BASE_URL` 仍可继续使用，代码会自动兼容到 `GS_SERVICE_BASE_URL`

### 2.2 训练服务机器

| 变量 | 用途 |
| --- | --- |
| `STORAGE_ROOT` | 服务器上的任务、日志、模型根目录 |
| `VIEWER_ROOT` | 仅保留兼容；当前服务器不再托管 viewer 静态资源 |
| `TRAINER_SERVICE_PUBLIC_BASE_URL` | 可选；trainer_service 返回给手机/浏览器访问的公开地址 |
| `TRAINER_SERVICE_AUTH_TOKEN` | 可选，保护内部 `/internal/tasks/*` |
| `SAM2_PYTHON` | 指向 `sam2_app` 的 Python |
| `PRUNING_PYTHON` | 指向 `3dgs_app` 的 Python |
| `COLMAP_COMPAT_REAL_EXE` | 指向服务器上的 `colmap` 可执行文件 |

## 3. 启动业务后端

从项目根目录执行：

```powershell
cd D:\Projects\3dgs-app
```

### 3.1 本地业务后端

```powershell
$env:STORAGE_ROOT = "D:\Projects\3dgs-app\storage"
$env:VIEWER_ROOT = "D:\Projects\3dgs-app\viewer"
$env:GS_SERVICE_BASE_URL = "http://<trainer-server>:9000"

backend\.venv\Scripts\python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

如果训练服务就在你本机：

```powershell
$env:GS_SERVICE_BASE_URL = "http://127.0.0.1:9000"
```

### 3.2 mock 联调

```powershell
$env:BACKEND_PIPELINE_MOCK = "true"
$env:GS_SERVICE_BASE_URL = "http://127.0.0.1:9000"
backend\.venv\Scripts\python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 3.3 后端健康检查

```text
http://127.0.0.1:8000/health
```

重点确认：

1. `status = ok`
2. `gs_service_base_url` 正确
3. `viewer_proxy_mode = local-static`

## 4. 启动 trainer_service

只有“运行训练服务的机器”才需要这一步。

### 4.1 本机或服务器通用命令

```powershell
cd D:\Projects\3dgs-app
conda activate 3dgs_app
python -m pip install -r trainer_service\requirements.txt
```

然后设置环境变量并启动：

```powershell
$env:STORAGE_ROOT = "D:\Projects\3dgs-app\storage"
$env:VIEWER_ROOT = "D:\Projects\3dgs-app\viewer"
$env:TRAINER_SERVICE_PUBLIC_BASE_URL = "http://<手机可访问的训练服务地址>:9000"
$env:TRAINER_SERVICE_AUTH_TOKEN = "replace-with-an-internal-secret"
$env:SAM2_PYTHON = "D:\miniconda3\envs\sam2_app\python.exe"
$env:PRUNING_PYTHON = "D:\miniconda3\envs\3dgs_app\python.exe"
$env:COLMAP_COMPAT_REAL_EXE = "D:\colmap-x64-windows-cuda\bin\colmap.exe"

python -m uvicorn trainer_service.app:app --host 0.0.0.0 --port 9000
```

### 4.2 训练服务健康检查

```text
http://127.0.0.1:9000/health
```

重点确认：

1. `status = ok`
2. `storage_root` 指向服务器目录
3. 如果配置了 `TRAINER_SERVICE_PUBLIC_BASE_URL`，`public_base_url` 应正确

## 5. 启动 Flutter 前端

```powershell
cd D:\Projects\3dgs-app\mobile_app
flutter pub get
```

### 5.1 Android 模拟器

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

### 5.2 真机

```powershell
flutter run --dart-define=API_BASE_URL=http://<你的电脑IP>:8000
```

说明：

1. `API_BASE_URL` 始终填业务后端
2. 手机端不直接访问训练服务任务 API
3. App 打开模型时，最终 `viewer_url` 仍然是业务后端本地 `/viewer/index.html?...`
4. 但 `viewer` 页面里的 `model` 参数已经指向远程训练服务的 `/storage/models/...`
5. 如果 backend 到 trainer_service 用的是 `127.0.0.1` 或内网地址，而手机需要访问模型文件，必须在 trainer_service 上额外配置 `TRAINER_SERVICE_PUBLIC_BASE_URL`

## 6. 当前部署前验收清单

至少确认下面这些点：

1. `backend /health` 返回的 `gs_service_base_url` 正确
2. `trainer_service /health` 返回的 `storage_root` 正确
3. 创建任务后，视频上传落在服务器 `STORAGE_ROOT/uploads/<task_id>/`
4. 点击开始训练后，任务能通过 HTTP 从 backend 转发到 trainer_service
5. `pipeline/cancel`、`mask-preview`、`mask-confirm` 都能通过 trainer_service 正常工作
6. 训练完成后，`model_url` 指向远程训练服务 `/storage/*`
7. 训练完成后，`viewer_url` 指向业务后端本地 `/viewer/index.html?...`
8. `PUT /api/v1/reconstructions/{task_id}/viewer` 能把 viewer 配置写回远程训练服务

## 7. 常见问题

- `pipeline/start` 连接失败：优先检查 `GS_SERVICE_BASE_URL` 和服务器上的 `trainer_service` 是否启动
- `viewer` 能打开但模型不显示：先看 `viewer_url` 里的 `model=` 参数是不是 `127.0.0.1:9000`，如果是，就给 trainer_service 配置 `TRAINER_SERVICE_PUBLIC_BASE_URL`
- 手机上的 WebView 报 `cdn.jsdelivr.net ... Failed to fetch`：当前 viewer 已切到本地 PlayCanvas 资源；如果还看到旧日志，清一下 App/WebView 缓存后再试
- 真机访问失败：`API_BASE_URL` 仍然只应填写业务后端地址，不要填训练服务
- 本地 backend 误报找不到 `ns-train`：说明你还在按旧链路理解；当前 backend 默认不直接依赖训练命令
