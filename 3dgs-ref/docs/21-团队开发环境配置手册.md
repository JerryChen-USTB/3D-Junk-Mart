# 团队开发环境配置手册

更新时间：2026-04-10

本文面向团队成员的日常开发场景，目标是让你从 `git clone` 开始，快速完成：

1. 本地业务后端配置
2. Flutter 开发环境配置
3. App 与本地 backend 联调启动

当前推荐架构：

```text
Flutter App
   -> 本地 backend
   -> 远程 trainer_service

viewer 继续由本地 backend 托管
训练任务、模型、日志由服务器 trainer_service 管理
```

当前团队共享训练服务地址：

```text
http://222.199.216.192:9000
```

如果后续服务器地址变化，只需要替换文中的 `GS_SERVICE_BASE_URL`。

---

## 1. 你本地需要安装什么

团队日常开发默认不需要本地安装：

1. COLMAP
2. CUDA
3. nerfstudio
4. SAM2
5. `trainer_service`

你本地通常只需要这些：

| 软件 | 建议版本 | 用途 |
| --- | --- | --- |
| Git | 最新稳定版 | 拉代码 |
| Python | `3.13.x` | 运行 backend |
| Flutter | `3.41.x` 附近 | 运行移动端 |
| Android Studio | 最新稳定版 | Android SDK / 模拟器 |
| JDK | `21` | Flutter Android 构建 |

先确认下面两个命令正常：

```powershell
python --version
flutter doctor
```

## 2. Clone 项目

```powershell
git clone <your-repo-url>
cd <你的本地仓库目录>
```

说明：

1. 文中的 `3dgs-app` 只是历史示例目录名，不是固定目录名
2. 请始终以你机器上真实的仓库路径为准
3. 例如你的仓库如果在 `D:\Projects\3DGS-Marketplace`，后面的命令都应替换成这个路径

如果你已经有仓库，只需要：

```powershell
cd <your-local-repo>
git pull
```

## 3. 配置本地 backend

### 3.1 创建虚拟环境并安装依赖

在项目根目录执行：

```powershell
py -3.13 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install --upgrade pip
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
```

验证：

```powershell
backend\.venv\Scripts\python.exe -c "import fastapi, uvicorn, httpx; print('backend ok')"
```

### 3.2 配置环境变量

在启动 backend 的同一个 PowerShell 窗口里执行：

```powershell
$env:STORAGE_ROOT="<你的本地仓库路径>\\storage"
$env:VIEWER_ROOT="<你的本地仓库路径>\\viewer"
$env:GS_SERVICE_BASE_URL="http://222.199.216.192:9000"
```

说明：

1. `STORAGE_ROOT` 和 `VIEWER_ROOT` 指向你本地仓库目录
2. `GS_SERVICE_BASE_URL` 指向远程训练服务
3. App 只连接本地 backend，不直接连接训练服务
4. 不要照抄别人的示例路径，必须换成你自己的实际仓库路径

### 3.3 如果你开了梯子或系统代理

如果首页商品列表报 `502`，通常是本地 backend 访问远程 `trainer_service` 时被代理接管了。

建议至少做这两件事：

1. 在梯子规则里把 `222.199.216.192/32` 设为 `DIRECT`
2. 启动 backend 前补上：

```powershell
$env:NO_PROXY="127.0.0.1,localhost,222.199.216.192"
$env:no_proxy=$env:NO_PROXY
```

如果当前 shell 已经带了代理变量，也一并清掉：

```powershell
Remove-Item Env:HTTP_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:HTTPS_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:ALL_PROXY -ErrorAction SilentlyContinue
Remove-Item Env:http_proxy -ErrorAction SilentlyContinue
Remove-Item Env:https_proxy -ErrorAction SilentlyContinue
Remove-Item Env:all_proxy -ErrorAction SilentlyContinue
```

### 3.4 启动 backend

```powershell
backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

启动后打开：

```text
http://127.0.0.1:8000/health
```

至少确认：

1. `status` 是 `ok`
2. `gs_service_base_url` 是 `http://222.199.216.192:9000`

如果你想先单独测远程训练服务是否可达，可以执行：

```powershell
curl.exe -v --noproxy "*" http://222.199.216.192:9000/health
curl.exe -v --noproxy "*" http://222.199.216.192:9000/tasks
```

进入 Flutter 项目目录：

```powershell
cd mobile_app
flutter pub get
```

如果 `flutter doctor` 还有未解决项，先补齐 Android SDK、platform-tools、license，再继续。

## 5. 启动 App

### 5.1 Android 模拟器

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

说明：

1. `10.0.2.2` 只适用于 Android 模拟器访问宿主机 backend
2. 这里填的是本地 backend，不是远程训练服务

### 5.2 Android 真机

推荐先用最简单的方式：

```powershell
flutter run
```

说明：

1. 如果手机是通过 USB 连着电脑调试，App 里后端地址直接填：

```text
http://127.0.0.1:8000
```

2. 如果手机不是 USB 调试，而是和电脑在同一局域网，App 里后端地址填：

```text
http://<你的电脑局域网IP>:8000
```

例如：

```text
http://192.168.1.10:8000
```

3. 真机不能用 `10.0.2.2`
4. 这里填写的始终是本地 backend 地址，不是远程训练服务地址
5. 如果你是 USB 调试但 `127.0.0.1` 依然不通，再补执行一次：

```powershell
adb reverse tcp:8000 tcp:8000
```

## 6. 推荐启动顺序

每次开发建议按这个顺序来：

1. 打开 PowerShell，进入项目根目录
2. 设置 backend 环境变量
3. 启动 backend
4. 新开一个终端进入 `mobile_app`
5. 执行 `flutter run`

最常用的一组命令如下：

```powershell
cd <你的本地仓库路径>

$env:STORAGE_ROOT="<你的本地仓库路径>\\storage"
$env:VIEWER_ROOT="<你的本地仓库路径>\\viewer"
$env:GS_SERVICE_BASE_URL="http://222.199.216.192:9000"
$env:NO_PROXY="127.0.0.1,localhost,222.199.216.192"
$env:no_proxy=$env:NO_PROXY

backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

另开一个终端：

```powershell
cd <你的本地仓库路径>\mobile_app
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

## 7. 联调时如何快速判断是否正常

### 7.1 backend 正常

打开：

```text
http://127.0.0.1:8000/health
```

应看到：

1. `status = ok`
2. `gs_service_base_url = http://222.199.216.192:9000`

### 7.2 trainer_service 正常

执行：

```powershell
curl.exe -v --noproxy "*" http://222.199.216.192:9000/health
```

应返回 `200 OK`。

### 7.3 App 正常

1. 首页可以打开
2. 创建任务后不报连接错误
3. 详情页可以看到任务状态变化

## 8. 常见问题

### 8.1 首页商品加载失败，提示 `502`

优先检查：

1. backend 是否已经重启并读取到最新 `GS_SERVICE_BASE_URL`
2. `http://222.199.216.192:9000/health` 是否从你本机可达
3. 梯子是否已经把 `222.199.216.192/32` 设为直连
4. 当前 shell 是否残留代理变量

### 8.2 首页显示 `0 个商品`

这不一定是错误。  
首页只展示“已发布”的任务；如果任务只是训练完成但还没发布，首页会是 `0`。

### 8.3 真机连不上 backend

优先检查：

1. 如果你是 USB 调试，App 里是否填写了 `http://127.0.0.1:8000`
2. 如果你走局域网，App 里是否填写了你电脑的真实局域网 IP
3. 真机里是否误填成了 `10.0.2.2`
4. 如果你走局域网，手机和电脑是否在同一网络
5. Windows 防火墙是否拦住了 `8000` 端口
6. 如果你走 USB 调试但 `127.0.0.1` 不通，再执行一次 `adb reverse tcp:8000 tcp:8000`

### 8.4 App 能打开，但模型不显示

优先检查：

1. backend `/health` 是否正常
2. 远程 `trainer_service` 是否正常
3. 当前任务是否已经训练完成
4. 返回的 `model_url` 是否能从手机访问

### 8.5 第 6 步进入 viewer 报 `404 Not Found`

最常见原因不是训练失败，而是你本地 backend 托管的 `viewer/` 静态文件不存在。

先确认：

```powershell
dir <你的本地仓库路径>\viewer
curl.exe -i http://127.0.0.1:8000/viewer/index.html
```

你本地 `viewer/` 目录里至少应该有这些文件：

1. `index.html`
2. `viewer.js`
3. `style.css`
4. `cache.html`
5. `cache-manager.js`
6. `model-cache.js`
7. `vendor\playcanvas-2.17.2.mjs`

如果 `viewer/` 目录是空的，直接在仓库根目录恢复：

```powershell
cd <你的本地仓库路径>
git fetch origin
git restore --source origin/main -- viewer
dir <你的本地仓库路径>\viewer
```

然后重新设置环境变量并重启 backend：

```powershell
$env:STORAGE_ROOT="<你的本地仓库路径>\\storage"
$env:VIEWER_ROOT="<你的本地仓库路径>\\viewer"
$env:GS_SERVICE_BASE_URL="http://222.199.216.192:9000"

backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

最后再次确认：

```powershell
curl.exe -i http://127.0.0.1:8000/viewer/index.html
```

如果这一步返回 `200`，第 6 步 viewer 一般就能正常打开。

## 9. 什么时候你才需要本地安装训练环境

只有在你要开发这些内容时，才需要继续配置本地 `trainer_service`、`3dgs_app`、`sam2_app`：

1. 训练流水线
2. Object Masking
3. 导出链路
4. CUDA / COLMAP / nerfstudio 相关问题

如果你只是做：

1. Flutter 页面
2. 业务后端接口
3. 商品发布与展示逻辑

那你本地不需要安装训练环境。
